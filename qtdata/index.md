# 量潮数据

量潮数据为高校科研团队与高新科技企业提供数据处理服务：把原始数据变成可靠、可直接使用的结构化数据。数据条目平均在 100 万以上、最大数十亿，数据量平均在 50 GB 以上、最大 10 TB。交付遵循科研领域的可复现标准，附带完整处理日志，供论文评审时溯源。

这条业务线的工作按数据从原料到成品的三个阶段组织——**采集、清洗、精炼**。下面是我们在这个三个阶段里的主要案例。

## 采集

把散在互联网和客户手里的原始数据完整、稳定地拿下来。

**高频电商价格采集**。源于量潮科技前身——厦门大学 China's Prices Project（CPP）课题组十年的积累：每天采集天猫和京东平台 1000 余个关键词、约 500 万数据点，用于编制中国高频线上价格指数。CPP 期间经历了从个人电脑定时爬虫到腾讯云服务器集群、从 13 人手动维护到自动化系统的演进，也留下了爬虫第 23 版、小文件 CSV 存储困境、MongoDB 方案设计这些具体经验。

承接采集类需求时，反爬虫强度是报价前必须评估的一项——它直接决定工时与风险。

## 清洗

把多个来源的数据弄干净、对齐，合并成一张能分析的表。

**问卷数据清洗与标准化**。把收回来的问卷数据处理成可直接进入分析流程的标准数据集。

**制衣厂生产效率数据合并**。客户的原始数据散在四个 Excel 文件里——产量（谁、哪天、哪道工序、完成多少件）、工序表（每个款式的标准工序、机器、时间）、返工记录、考勤记录。我们把四个数据源按**款号、日期、员工**三个维度合并成统一的分析数据集，用于员工绩效计算、款式生产效率分析、返工率影响评估与成本核算。合并的依据是制造业的产值公式：

```
产值 = 员工 × 工序 × 产量
```

## 精炼

把干净的数据变成能支撑结论的数据集或指数，并让它可查、可看。

**高频价格指数计算**。用 2026 年的技术栈重做 CPP 的经典课题：以对象存储替代本地文件、ClickHouse 替代 MongoDB、Python 自动化流水线替代手动运维，构建一套自动化、高并发、可复用的价格指数计算与可视化体系，实现列式查询下的高频（按日）指数构建。

**面向论文分析的结构化数据集**。面向高校经管方向的研究者，把原始数据清洗、加工为可直接用于计量分析的语料，并保证处理过程可复现。

## 这一类业务的难点

订单规模不大（多为数千元到一两万）、周期短（几周结项）、客户对质量要求高。真正的难点不在单个技术点，而在**保持经营效率、减少隐形摩擦**——需求要说清、报价要透明、过程要跟得住。这也是量潮数据持续把隐式经验写成显式文档、再转成代码的原因。
